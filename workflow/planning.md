# 계획

개정: 2026-11-17 · 관리 구조 버전: `5`

## 6. [계획]

프로젝트 목표·요구사항·제약·자료를 입력으로 받으며 고정된 사용자 입력 형식을 요구하지 않는다. 기존 결정과 원자료를 먼저 확인한다. 초기 구조 생성만 [구조](records-layout.md)를 읽고, 기존 구조 전환은 사용자가 요청한 경우에만 [전환](migration.md)을 적용한다. 기존 작업의 계획에 전체 구조 전환을 선행시키지 않는다.

### 요구사항 확인

자료로 해소되지 않는 목표·필수 요구·제외 범위·품질 제약·완료 조건을 영향이 큰 순서로 한 번에 1~3개 질문한다. 선택지·권장안·차이를 필요한 만큼 설명하고 확정 답변을 다시 묻지 않는다. 확정 범위의 구현 선택은 담당자가 판단하며 외부 동작·공개 인터페이스·비용·수락 기준 변경은 요구사항 결정으로 구분한다. 사용자의 위임 범위·근거를 기록한다.

답변 대기 중 독립 조사는 가능하나 미확정 답변에 의존하는 설계·지시서는 확정하지 않는다. 무응답·시간 경과를 동의로 간주하지 않는다. 결정·남은 질문은 plan에 남기고 인터뷰 전문·별도 문서를 기본 생성하지 않는다. 모호함이 해소됐거나 판단을 위임받으면 확정하며 그렇지 않으면 미확정 부분·재개 조건을 인계한다.

### 분할과 지시서

요구사항 ID를 부여하고 기능·책임·입출력·공유 자원으로 작업을 나눈다. 명명·용어·문체·데이터 형식·공개 인터페이스 등 공통 기준은 plan에 한 번만 둔다. 독립 검증·인계 가능한 단위로 분할하며 자료량·예상 변경량·검증 난도·외부 의존성으로 작업량 소/중/대와 컨텍스트 분할을 판단한다. 예상 난도로 최초 모델을 높이지 않는다.

작업 문서는 짧은 한국어 Markdown을 유지한다. 관련 항목을 묶고 공통 규칙은 경로·절·버전으로 참조한다. 다음 정보가 지시서와 필수 입력을 합쳐 충족되면 되며 항목마다 별도 긴 절을 만들 필요는 없다.

- [작업 메타정보](records-state.md#식별과-메타정보), 요구사항 ID·목적·목표, 포함/제외·수정 허용/금지 범위·산출물 위치.
- 입력·기준 버전·접근 조건, 배경·사용자 결정·위임받은 판단.
- 선행 ID·필요 수락/검증·사용 산출물 버전·시작 조건, 파일/공유 자원 소유권, 인터페이스·관련/필수 하위/후속 작업. 해당 없음과 미확정을 구분한다.
- 병렬 가능/조건부 가능/불가, 함께 수행 가능한 ID/그룹, 근거·해제 조건·동시 금지 대상·통합 순서. 파일 외에도 설정·잠금 파일·빌드 출력·Git index·시험 장비와 입력 안정성을 확인한다. 미확정은 가능으로 보지 않고 별도 병렬 원장을 만들지 않는다.
- 제약·위험·수행 지침, [TC 원본 규칙](records-evidence.md#5-테스트케이스-원본)에 따른 테스트케이스 수준의 완료 조건·필수 검증 목표·방법의 선택 범위. 환경상 불가능한 검증·영향도 명시한다.
- 작업량·분할 판단·역할별 모델과 사용자 예외, 재시도의 실패 근거·누계·남은 상향 한도, 검토 담당·후속 인계.

표준 방식은 plan·index와 작업별 원본을 작성하고 조건에 따라 계획됨/준비됨으로 둔다. 간소 방식은 같은 핵심 정보를 짧은 지시·인계에 담는다. 결과/증빙은 공통 원본 규칙을 따르고 작업별 예외만 추가한다. 상세 TC 목록을 plan·index에 복제하지 않는다. 형식만 바꾸는 AI용 사본은 만들지 않는다.

### 자체 검토와 종료

작성자가 요구사항→작업→TC의 대응, 관측 가능한 기대 결과, 누락/충돌·의존성·권한·모델, 새 담당자의 입력 접근과 착수 가능성을 직접 검토하고 발견 사항을 반영한다. 작성 과정에서 이미 검토한 부분은 반복하지 않고 검토 범위·결론을 짧게 기록한다. **계획 자체 검토를 위한 별도 에이전트를 호출하지 않는다.**

미확정 요구사항은 완료/준비됨으로 표시하지 않는다. 기존 실행 결과는 제출 상태만 반영하며 통합 수락을 대신하지 않는다. 계획 산출물 완료와 실행 Task의 준비·수락을 구분하고 제작을 시작하지 않는다. 종료 시 경로·의존 관계·사용자 결정·다음 행동을 인계한다. 추후 TC 개수·내용·현황 요청은 [공통 조회 규칙](records-evidence.md#tc-현황-조회)을 사용한다.
