## 14. [커밋] 변경 조사와 커밋리스트 작성

### 범위와 출력 위치

요청된 범위의 실제 Git 변경을 조사해 커밋리스트 텍스트 파일만 작성한다. 목록 파일 작성 외에 소스·관리 문서·Git index·설정·이력을 변경하지 않으며 `git add`·`git commit`·추적 해제도 실행하지 않는다. 제작·수락 단계가 아니며 `[총괄]` 호출에 포함되지 않는다.

- 사용자 지정 프로젝트 루트와 Git 저장소 경계를 확인한다. Git 루트는 조사 기준이고 출력 경로는 프로젝트 루트 기준 상대 경로다. 프로젝트가 저장소의 하위 폴더이면 경로 접두를 정확히 변환한다. 루트가 미지정이고 저장소 하나가 명확할 때만 저장소 루트를 사용할 수 있다. 여러 저장소를 한 목록에 섞거나 범위 밖 파일을 임의로 포함하지 않는다.
- 출력은 사용자 지정 경로를 우선하고 기본은 프로젝트 루트의 `commit-list.txt`다. 기존 생성 목록은 요청 범위에서 재생성할 수 있지만 같은 이름의 무관한 파일은 보존한다. 목록 자체가 작업 트리에 새 변경으로 나타날 수 있다.
- `.ai-work/`와 생성하는 커밋리스트는 기본 제외한다. Git 포함·내부 식별 정보 노출의 예외는 [2절](records.md)을 따른다. 작업 ID는 내부 분류에만 사용하며 메시지·그룹 제목·설명에 넣지 않는다.

### 조사와 파일 단위 분류

1. tracked 파일의 staged·unstaged diff와 무시되지 않은 untracked 파일 내용을 확인한다. 수락된 작업도 실제 최신 변경으로 판단하며 제출 이후 변경을 놓치지 않는다.
2. 작업지시 단위 또는 의미 있는 변경 단위로 관련 코드·테스트·문서를 묶는다. **한 파일은 하나의 추천 커밋에만 포함한다.** 같은 파일이 여러 목적에 걸치면 관련 묶음을 합치고 필요한 경우 이유를 짧게 적는다. 파일 단위로 묶기 어려운 항목은 보류 사유와 필요한 결정을 알린다. 라인·패치 단위 분할, 부분 스테이징 절차와 별도 분할 관리 기록은 만들지 않는다.
3. staged·unstaged 내용과 작업 트리의 최종 내용을 구분한다. 파일 전체를 staging하면 현재 작업 트리 내용으로 index가 갱신되어 기존 staged 변경이 바뀌거나 취소될 수 있다. 상쇄되는 변경이나 기존 staging 의도를 유지해야 하는 부분은 표시하되 실제 상태는 보존한다.
4. 스테이징 명령에는 이름 변경의 이전·새 경로와 삭제 경로도 포함한다. 현재 index·작업 트리 상태에서 각 경로를 처리할 수 있는지 확인한다. 후보 변경의 누락·중복을 확인하고 제외·보류 이유는 명령 블록 밖에 적는다. 이미 추적·스테이징된 관리 파일은 해제하지 않고 필요한 조치만 알린다.
5. 조사 기준 `HEAD`·시각·변경 상태와 작성 완료 시점을 대조한다. 생성 목록 자체를 제외한 상태가 바뀌었으면 영향받은 부분만 다시 검토한다. 후보가 없으면 없음으로 보고하고 가상 커밋을 만들지 않는다.

### 메시지 관례와 결과 형식

대상 디렉터리의 사용자 지시·기여 지침·프로젝트 규칙을 우선한다. 별도 규칙이 없으면 `HEAD`를 포함한 최근 최대 30개 조상 커밋의 실제 제목·본문에서 언어, 접두어·scope, 본문·footer 형식을 파악한다. 이력이 짧으면 있는 만큼 사용하고, 이력이 없거나 형식이 불명확하면 관측 근거와 제안 형식을 밝힌다. 디렉터리 간 규칙 충돌은 파일 단위 묶음 조정으로 해결 가능한지 확인하고 남은 결정만 질문한다. 확인되지 않은 이슈 번호·서명·검증 통과 주장은 만들지 않는다.

목록 앞에는 프로젝트 루트 절대 경로, `HEAD` 또는 초기 커밋 전 상태, 조사 시각·범위, 관례 근거와 명령에 사용하는 shell을 짧게 적는다. 각 그룹은 순서 번호, 추천 메시지, 스테이징 명령 블록으로 구성한다. 번호는 메시지에 포함하지 않고 본문은 실제 관례에 따라 작성한다.

파일마다 `git add -- <인용한 상대 경로>` 형태의 완결된 명령을 한 줄씩 작성한다. 경로는 프로젝트 루트 기준이며 명령도 그 위치에서 실행하도록 안내한다. 별도의 파일 목록을 중복 작성하지 않는다. 명령 줄에는 글머리표·상태 문자·인라인 주석을 붙이지 않고, 여러 줄을 잇는 shell 연결 문법도 사용하지 않는다. 공백·특수 문자를 보존하도록 사용자의 shell에 맞게 경로를 인용·이스케이프한다. Git pathspec 특수 문자가 있는 경로는 문자 그대로 지정되도록 처리한다. 기존 환경 정보에서 shell을 확인하고, 알 수 없으면 필요한 정보만 질문한다.

```text
커밋 1

커밋 메시지:
[프로젝트 관례에 맞는 제목과 필요한 본문]

스테이징 명령 — 프로젝트 루트에서 실행:
git add -- "src/example.rs"
git add -- "tests/example.rs"
```

위 예시는 Bash 기준이다. 파일은 설명과 메시지를 포함한 작성 시점의 제안이므로 전체를 실행하지 않는다. 사용자는 현재 커밋할 그룹의 명령 줄만 복사해 실행하고, 해당 커밋을 마친 뒤 다음 그룹으로 진행한다. 기존 staged 변경도 커밋에 포함될 수 있으므로 실제 스테이징·커밋 전에 현재 diff와 staged 내용을 목록에 대조하도록 안내한다. 목록 경로·조사 기준·보류 사항을 인계하며, 명령 작성만으로 실제 실행이나 변경 반영·통합 수락을 선언하지 않는다.
