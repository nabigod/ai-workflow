# 총괄

개정: 2026-11-08 · 관리 구조 버전: `5`

## 11. [총괄] 자동 운영

### 진입·범위·시작 조건

- 사용자가 직접 `[총괄]`을 호출하면, 이미 확정된 계획의 지정 범위에 대해 하위 에이전트 배정, 실행·통합 전환, 완료 조건을 충족하기 위한 범위 내 REV 생성·실행·재검토를 위임한 것으로 본다. 기존 단계 규칙에서 요구하는 매 단계별 사용자 지시는 이 범위에서 총괄 배정으로 대신한다. 초기 계획 생성과 중요한 재계획은 포함하지 않는다.
- 프로젝트·관리 위치·대상 Task ID 또는 명확한 대상 집합·계획 버전을 확인한다. 범위에 포함되는 필수 하위 작업과 제외 작업도 적는다. 사용자가 전체를 지정하지 않았으면 프로젝트 전체로 확대하지 않는다. 대상이 불명확한 부분만 확인하며 범위 밖 선행 작업은 자동 실행하지 않는다.
- 호출 여부는 [1절](common.md)로 판단한다. 총괄 요청은 실행 종료나 사용자 중지로 배정 효력이 끝난다. 이후 결과 제출·일반 메시지·준비됨 표기만으로 자동 재개하지 않는다.
- 시작 전에 관리 구조, 담당 인계, 의존 관계, 입력·수락 기준, 모델 프로필, 하위 에이전트 시작·상태 확인·대기·중단 기능을 확인한다. 시작·중단 시 실제 확인한 기능과 미검증 기능을 구분한다. 하위 에이전트를 제어할 수 없는 환경에서는 자동 운영을 시작하지 말고 수동 수행 등 대안을 인계한다.
- 지정된 시간·토큰·비용 한도와 환경이 강제하는 한도를 확인한다. 사용자 미지정 항목은 미지정으로 기록하고 임의의 수치를 승인값으로 쓰지 않는다. 한도를 정확히 관측·집행할 수 없으면 시작 전에 그 제한을 알리며, 엄격한 한도가 필수 조건이면 집행 수단 확보 전 배정하지 않는다. 자연어 한도만으로 실행 중 호출을 정확한 시점에 끊는다고 보장하지 않는다.
- [담당·소유권](common.md)·[모델·재시도](models.md)의 최신 버전 선택·Sol 사용량 제한 대체·상향 범위를 벗어난 모델 변경, 핵심 요구사항 변경, 범위 확대, 승인 한도 밖 비용·새 권한·환경 준비가 필요하면 관련 작업을 중단하고 사용자에게 필요한 결정을 요청한다. 계획·완료 조건을 낮춰 실행을 계속하지 않는다.

### 의존 관계와 문서의 기준

작업 지시의 선행 조건·입력 버전·공유 자원·관련 작업은 [6절](planning.md)의 필수 내용을 따른다. 상태·판정의 원본은 [4절](records.md)을 기준으로 한다. 총괄은 배정 전에 실제 작업 문서·버전·담당을 대조하며 현황판이나 오래된 index.md만으로 시작하지 않는다. 순환 의존·누락된 ID·불일치가 있으면 영향받는 작업을 보류하고 원인을 기록한다.

일반 선행 조건은 필요한 작업의 수락을 확인한다. REV는 수정 대상 버전과 수정 지시의 준비 여부를, 필수 VAL은 계획에서 정의한 검증 가능한 산출물을 시작 조건으로 삼는다. 상위 Task의 최종 수락을 먼저 요구해 순환 의존을 만들지 않는다. 선행 결과 변경은 [5절](records.md)의 영향 평가를 거친다.

### 배정·실행·통합 반복

1. 총괄은 [담당·소유권](common.md)·[모델·재시도](models.md)의 역할별 최초 배정 단계와 실제 모델을 대조하고, 상향 배정에는 지정 단계의 동일 문제 실패 2회 및 남은 상향 한도의 근거를 확인한다. 지시서의 권고만으로 최초 실행을 높게 배정하지 않는다. 최초 범위·입력·중단 조건을 index.md에 기록한다. 실제 환경의 동시 실행 제한을 따른다.
2. 총괄은 계획 담당자가 작업지시서에 남긴 병렬 가능 판단·근거·조건을 읽고, 현재 선행 조건·입력 버전·공유 자원·담당 인계와 실행 슬롯을 다시 확인한다. 독립적으로 수행 가능한 작업은 각각 별도 하위 에이전트를 호출해 동시에 배정한다. 확정 계획과 총괄 요청 범위 안의 병렬 배정에는 별도 승인을 요구하지 않는다. 조건부 가능은 조건 충족을 확인한 뒤 배정하며, 불가·미확정·판단 누락 항목은 병렬화하지 않는다. 순차 수행의 시작 조건을 충족하면 순차로 진행하고, 병렬 판단 보완이 필요하면 계획 담당자에게 인계한다. 사용자의 동시 실행 제한과 시간·사용량·비용 한도 및 환경 슬롯 한도를 지키며, 슬롯 부족은 대기·순차 배정으로 처리한다.
3. [담당·소유권](common.md)·[모델·재시도](models.md)의 위임 기준에 따라 실행 담당자에게 배정한다. 담당자는 [7절](execution.md)에 따라 제작·자체 검증 후 결과를 제출한다.
4. 총괄은 완료 이벤트 또는 대기 도구로 결과를 기다리고, 제출 시각·산출물 버전·문서 인계를 확인한 뒤 별도 통합 담당자에게 [8절](integration.md)의 검토를 배정한다. 프로세스 종료만으로 결과 제출이나 수락을 추정하지 않는다. 독립 작업은 다른 작업의 종료를 기다릴 필요가 없지만, 같은 산출물을 수정하는 실행과 그 버전을 검토하는 통합은 겹치지 않는다. 병렬 통합은 검토 대상·문서 소유권이 분리된 경우에만 배정하고, 공유 `integration.md` 갱신과 범위 전체의 최종 결합·판정은 한 통합 담당자에게 직렬로 맡긴다.
5. 통합 판정에 따른 상태 이동과 REV 식별은 [4절](records.md)을 따른다. 수정이 필요하면 통합 담당자가 지시를 작성하고 총괄이 범위·시작 조건을 확인해 실행과 재검토를 배정한다.
6. 결과마다 후속 시작 조건을 다시 확인한다. 외부 조건·사용자 검증·수정 한도로 멈춘 작업은 원인과 다음 행동을 기록하고 독립 작업만 계속한다. 사용자 전체 중지나 전체 실행 한도 도달 시에는 독립 작업도 새로 배정하지 않고 아래 전체 중지 절차를 수행한다.
7. 지정 범위의 필수 작업이 수락되면 통합 담당자에게 범위 전체의 연결·누락·잔여 수정 검증을 맡긴다. 유효한 기존 검증은 재사용한다. 여기서 필요한 REV도 같은 범위와 중단 조건 아래 처리한다.
8. [8절](integration.md)의 통합 판정에 따라 범위 완료 또는 미완료로 종료한다. 실행 가능한 작업 없이 외부 입력만 필요하면 인계 후 종료한다.

### 병렬 수행 불가 발견 시 보고와 조정

- 실행·통합 담당자가 공유 파일·문서·외부 자원 충돌, 숨은 선행 의존성, 입력 버전 변경 등으로 병렬 수행이 불가능함을 발견하면 영향받는 쓰기·시험을 즉시 보류하고 총괄에게 보고한다. 관련 작업 ID·자원·관측 근거·진행 중 명령·보존된 변경·필요한 조건을 짧게 전달한다. 다른 담당자의 파일을 덮어쓰거나 임의로 담당·순서를 바꾸지 않는다.
- 총괄은 관련 담당자의 현재 작업과 명령을 확인하고 필요한 중단·소유권 인계를 조정한 뒤 순차 전환, 대기, 승인 범위 안의 자원 분리 또는 재배정을 지시한다. 기존 작업 문서의 조건과 `index.md`의 배정·다음 행동만 갱신하며 별도 충돌 원장을 만들지 않는다. 중요한 설계·범위·수락 기준 변경은 계획 담당자와 사용자에게 인계한다.
- 보고한 담당자는 총괄 지시와 재개 조건 확인 후 작업을 이어간다. 충돌과 무관한 읽기·조사는 기존 허용 범위에서 가능하지만, 영향받는 작업은 임의 재개하지 않는다. 총괄이 응답할 수 없으면 미제출 변경·근거·재개 조건을 보존해 인계한다. 다른 독립 작업의 계속 여부는 총괄이 판단한다. 대기·막힘 등 상태는 [4절](records.md)을 따르며 충돌 보고만으로 새 REV나 실패 판정을 만들지 않는다.

### 운영 기록·재시도·종료

총괄은 index.md에 실행 식별자, 요청 시각, 대상·계획 버전, 운영 상태, 갱신 담당, 적용 모델 프로필과 예외, 활성 작업·하위 에이전트 식별자와 가능한 명령 식별자, 마지막 확인 시각, 다음 행동을 남긴다. 실제 모델·시도 이력·사용량 상세는 작업 문서나 실행 기록으로 연결하고, 시간·사용량 한도의 지정값과 관측 범위, 배정에 필요한 잔여 시도 한도, 현재 병렬 배정·자원 소유권과 순차 전환 사유, 중단 이유·미확인 실행·재개 조건만 요약한다. 에이전트·명령 식별자는 시작 시 확보하며 종료 후에는 결과와 함께 정리한다.

운영 상태는 실행 중·결과 대기·중지 처리 중·중지됨·완료·미완료 종료로 구분한다. 이는 총괄 실행의 상태이며 [4절](records.md)의 작업 상태 폴더를 추가하거나 대체하지 않는다. 실행 프로세스 상태를 확인할 수 없으면 마지막 확인 시각과 확인 불가를 표시한다.

재시도·모델 상향·중단은 [담당·소유권](common.md)·[모델·재시도](models.md)의 공통 정책을 적용한다. 총괄은 매 재배정 전에 같은 문제의 누적 시도와 잔여 한도를 확인하고, 상향 1회가 실패한 문제를 다른 REV나 단계로 옮겨 재시작하지 않는다.

### 전체 중지와 중단 확인

`[총괄] 중지` 또는 자연어로 총괄 전체 중지를 요청하면 다음 순서를 따른다. 이 절은 중지 기능의 운영 요구사항이며 현재 앱의 정지 버튼이나 실행기의 구현을 자동 변경하지 않는다.

1. 새 배정과 자동 재시도를 즉시 금지하고, 가능하면 운영 상태를 중지 처리 중으로 기록한다. 중지 요청은 이후 도착한 완료 이벤트나 대기열 작업보다 우선한다.
2. 해당 총괄이 배정한 실행·통합 하위 에이전트와 추가로 생성된 자손 에이전트까지 확인해 중단을 요청한다. 다른 사용자의 작업이나 무관한 대화는 중단하지 않는다.
3. 해당 실행이 시작한 명령·백그라운드 작업을 식별하고 허용된 제어 기능으로 종료를 요청한다. 도구 호출이 이미 수행한 외부 작업이나 저장된 파일 변경은 자동 취소·되돌리기 대상이라고 가정하지 않는다.
4. 요청 접수와 실제 중단 확인을 구분한다. 일부 에이전트·명령의 중단이 불가능하거나 확인되지 않으면 남아 있는 식별자·영향·사용자가 해야 할 조치를 보고한다. 확인되지 않은 상태를 전체 중지 완료로 표시하지 않는다.
5. 갱신 담당이 멈춘 것을 확인한 뒤 보존된 파일·미제출 변경·마지막 유효 검증·현재 위치·재개 조건을 최소한으로 기록한다. 중지된 작업을 임의로 완료·실패·취소로 바꾸거나 중단 요청을 처리하면서 제작을 이어가지 않는다.
6. 전체 중단이 확인되면 중지됨으로 기록하고 종료한다. 확인할 수 없는 대상이 남으면 중지 처리 중과 확인 불가를 유지해 인계하며 무한 대기하지 않는다. 이후에는 명시적 재개 요청만 배정을 허용한다.

긴 도구 호출이나 외부 작업은 취소 요청을 즉시 처리하지 못할 수 있다. 상위 턴의 중단이 모든 하위 에이전트·명령에 자동 전파된다고 보장하지 않는다. 정지 버튼으로 총괄 자체가 먼저 멈추면 위 정리 절차가 수행되지 못할 수 있다. 지원되는 실행기는 상위 중단을 감지해 등록된 자식과 명령으로 취소를 전달하도록 별도로 구현·시험한다. 문서 지침만으로 이를 구현했다고 보고하지 않는다.

정지 버튼 사용 후 사용자가 `[총괄] 중단 확인` 또는 “작업을 재개하지 말고 남은 실행을 중단하고 상태만 정리해 줘”라고 요청하면 위 절차의 잔여 실행 확인·중단·기록만 수행한다. 이는 자동 수행 재개 권한이 아니다. 총괄이나 수집기가 끊긴 동안 기록이 오래됐다는 이유만으로 잔여 실행이 없다고 판단하지 않는다.

### 재개

`[총괄] 재개`에는 기존 실행이나 대상 범위를 확인한다. 중지 이유가 해소됐는지, 잔여 에이전트·명령이 없는지, 현재 담당·문서 위치·미제출 변경·실제 산출물·검증 버전이 일치하는지 확인한다. 미확인 실행과 소유권 충돌이 남아 있으면 배정하지 않는다. 유효한 결과와 수락은 유지하고 영향받는 검증만 다시 수행하며, 완료 작업을 처음부터 재실행하지 않는다. 기존 범위·모델·한도·재시도 횟수는 명시적 변경이 없는 한 유지하고 누적 사용량을 확인한다. 이미 한도에 도달했으면 단순 재개 요청만으로 한도를 초기화하거나 확대하지 않는다.

총괄 종료 후의 일반 수동 요청은 해당 단계만 수행한다. 총괄 도중 사용자검증 등 별도 수동 쓰기 요청이 들어오면 관련 배정을 보류하고 [담당·소유권](common.md)·[모델·재시도](models.md)에 따라 담당을 인계한다. 상태 조회는 [1절](common.md)의 읽기 범위만 따른다.
