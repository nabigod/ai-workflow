# 모델 배정·재시도

개정: 2026-11-12 · 관리 구조 버전: `5`

### 모델과 실행 환경

환경별 모델 계열과 단계는 다음과 같다. 각 계열의 최신 버전을 기본으로 하며, 표의 버전은 사용자가 지정한 기준값이다. Codex와 Cursor 2·3단계의 기준은 2026-11-07 지정을 유지하고, Cursor 1단계는 2026-11-12 지정에 따라 Claude Haiku 5.5·`high`로 개정했다. 배정 시작 시 해당 환경의 모델 목록과 공식 안내에서 최신 버전·실제 선택명·사용 가능 여부를 확인해 적용 버전을 기록한다. 실행 중인 담당자의 모델을 새 버전 발표만으로 교체하지 않는다. 최신 여부를 확인할 수 없으면 기준값과 확인 한계를 밝히고 실제 사용 가능한 설정을 확인한다. 이 표는 배정 정책이며 계정별 가용성을 보증하지 않는다.

| 환경 | 1단계 | 2단계 | 3단계 |
|---|---|---|---|
| Codex | GPT Luna 최신 버전 — 기준 6 (`gpt-6-luna`) | GPT Sol 최신 버전 — 기준 6.1 (`gpt-6.1-sol`); 사용량 제한 시 6 → 5.6 | GPT Astra 최신 버전 — 기준 6 (`gpt-6-astra`) |
| Cursor | Claude Haiku 최신 버전 · `high` — 2026-11-12 기준 5.5 | Claude Sonnet 최신 버전 — 기준 5.5 | Claude Opus 최신 버전 — 기준 5.5 |

| 역할 | 최초 배정 단계 | 적용 |
|---|---|---|
| 계획 | 3단계 | 사용자가 직접 요청하는 초기 계획·중요한 재계획 |
| 총괄 | 2단계 | 자동 운영의 배정·상태·중지·재개 관리 |
| 실행 | 1단계 | 지정 작업 및 범위 내 REV 구현·자체 검증 |
| 통합 | 2단계 | 별도 담당의 검토·수락·최종 연결 검증 |
| 사용자검증 | 1단계 | 확정 기준에 대한 사용자 시험 안내·근거 확인·검증 기록 |
| 커밋목록 | 1단계 | 의미 있는 변경을 파일 단위로 묶어 커밋리스트 작성 |

- Cursor 1단계가 적용되는 실행·REV·사용자검증·커밋목록은 모두 **Claude Haiku 최신 버전 + `high`**를 요청한다. 5.5는 현재 기준값이며 버전 고정 지시가 아니다. 모델 계열을 임의로 대체하지 않고 최신 여부·실제 선택명·추론 강도 지원을 배정 시 확인한다. [Cursor Haiku 안내](https://cursor.com/docs/models/claude-haiku-5-5)
- 사용자 지정 환경·모델·추론 강도를 우선하고, 미지정 값은 위 프로필을 적용한다. 추론 강도를 선택할 수 있는 모델에는 `high`를 요청한다. 해당 설정이 없는 모델은 지원 여부를 확인해 `설정 미지원`과 실제 기본 설정을 기록하며 `high`를 적용했다고 주장하지 않는다. 실제 선택명·식별자는 해당 환경에서 확인하고 다른 제공자나 버전의 식별자를 추정하지 않는다. 사용자가 특정 버전을 고정하면 최신 버전 정책보다 우선하며, 단계표 밖 모델의 상향 경로는 임의로 정하지 않는다.
- **최초 시도는 역할별 지정 모델로 시작한다.** 사용자에게 별도 모델 지정이 없으면 [모델 배정표](models.md)의 최초 배정 단계를 준수한다. 계획·통합·총괄 담당자는 예상 난도·위험·작업량·시간 절약을 이유로 최초 실행이나 REV를 상위 모델에 배정할 수 없다. 작업지시서의 성능 권고도 이 기준을 변경할 권한이 아니다. 지정 모델이 없거나 사용 불가능하면 제한과 인계 방법을 보고하며 상위 단계로 건너뛰지 않는다. 품질 문제에 따른 상향은 아래의 실제 실패 요건을 충족한 경우에만 허용한다.
- 단계 태그나 문서만으로 현재 대화의 모델은 바뀌지 않는다. 지원되는 위임에는 프로필을 명시하고, 직접 수행에는 사용자가 선택한 실제 모델을 확인한다. 고급 모델이 직접 수행한 일을 저렴한 모델에 위임했다고 기록하지 않는다.
- 요청 설정과 실제 확인된 설정을 구분한다. 확인할 수 없으면 `확인 불가`로 기록한다. 위의 추론 강도 설정 미지원 예외 외에 필요한 모델 선택·설정이나 위임이 지원되지 않으면 제한과 수동 인계 등 대안을 알리고, 지정 프로필을 적용했다고 주장하지 않는다. 자동 모드의 모델·위임 기능은 시작 조건이므로 확보되지 않으면 배정하지 않는다. 수동 모드에서 지정 프로필을 적용할 수 없으면 사용자에게 가능한 수행 방식을 확인한다.
- 작업 실패를 이유로 계획·총괄의 모델 계열·단계를 자동 변경하지 않는다. 실행·통합의 품질 문제에 따른 상향은 아래 정책을 따른다. Codex Sol의 사용량 제한에 따른 버전 대체는 다음 규칙으로 구분한다.

### Codex Sol 사용량 제한 시 대체

- Codex의 2단계 배정에 실제 사용량 제한이 확인되면 **GPT Sol 최신 버전 → GPT-6 Sol → GPT-5.6 Sol** 순서로 사용 가능한 모델을 시도한다. 2026-11-07 기준 순서는 **6.1 → 6 → 5.6**이다. 이미 선택·확인한 같은 버전은 중복 시도하지 않는다. 총괄·통합과 실행의 2단계 상향 배정에 공통 적용한다. 사용자검증·커밋목록의 최초 배정은 1단계이며 이 대체 규칙을 이유로 Sol에 배정하지 않는다.
- 이 순서 안의 대체는 별도 승인 없이 허용한다. 각 후보의 실제 선택명·접근 가능 여부를 확인하고, 제공되지 않는 후보는 사유를 남겨 건너뛴다. 일시적 도구 오류나 작업 실패를 사용량 제한으로 간주하지 않는다. 계정 전체 제한·사용자 지정 총량 한도 등 모든 후보에 적용되는 한도는 모델 변경으로 우회하지 않는다. 후보를 모두 사용할 수 없으면 반복 호출하지 않고 제한과 재개 조건을 인계한다.
- 대체는 같은 2단계 안의 버전 변경이며 품질 문제의 상향이나 새 수정 시도가 아니다. 모델별 실제 시도는 구분하되 동일 문제의 재시도 누계·남은 한도는 이어받는다. 사용량 제한으로 시작하지 못한 호출은 수정 시도로 세지 않고, 중단 전 실제 수행한 수정·검증은 보존한다.
- 현재 담당자의 작업·명령 중단과 미제출 변경·문서 소유권을 확인한 뒤 인계한다. 총괄 자신이 제한된 경우에도 같은 경계를 지키며, 환경이 대화 모델 전환이나 담당 인계를 지원하지 않으면 가능한 수동 전환 방법을 안내한다. 대체 사유·선택 모델·적용 시점은 기존 운영 기록에 남기며, 요청 정책을 실제 전환 완료로 기록하지 않는다.

### 동일 문제의 재시도와 모델 상향

수동·자동 모드의 실행·통합에 공통 적용한다. **지정 모델로 최초 시도 → 실패 시 같은 모델로 수정 재시도 1회 → 동일 문제에서 총 2회 실패가 확인되면 바로 위 단계 모델로 1회 → 다시 실패하면 중단·보고·인계**를 기본 한도로 한다. 최초 시도를 포함해 지정 단계에서 총 2회 시도하며, 성공하면 상향하지 않는다. 누적 실패가 이미 2회 이상이면 기록을 확인하고 남아 있는 상향 1회만 사용할 수 있다. 상위 단계가 없거나 사용할 수 없으면 실패 근거와 재개 조건을 보고하고 인계한다. 두 단계 연속 상향은 허용하지 않는다.

- 한 번의 수정 재시도는 실패 근거 확인, 원인에 따른 수정 또는 검토 방법 보완, 관련 검증으로 구성한다. 개별 도구 호출·테스트 실행 횟수를 세지 않는다. 각 시도는 검증 가능한 결과로 마감하고, 실패한 수정·검증을 반복하면서 한 번의 시도로 묶지 않는다. 새로운 근거나 수정 없이 같은 시도를 반복하지 않는다.
- 권한·입력·외부 환경 부족으로 의미 있는 진행이 불가능하면 모델 상향 없이 인계한다. 검증 기준을 낮추거나 원인 미확인을 해결로 처리하지 않는다.
- 문제는 수정 대상과 재현 조건·실패 근거로 추적한다. 작업 문서에 모델별 시도 횟수·관측 결과·남은 한도를 기록하며, REV ID·에이전트 변경이나 중지 후 재개로 초기화하지 않는다. 같은 문제를 다른 작업으로 인계하면 누계도 연결한다.
- 상향 전 지정 단계에서 동일 문제에 대해 실제 실패한 2회의 근거를 확인한다. 계획의 난도 예상, 통합의 모델 추천, 같은 실패 로그의 중복 기록은 실패 횟수가 아니다. 상향할 때 각 시도의 모델·변경·검증·실패 근거, 확인된 사실과 남은 가설, 현재 산출물 버전을 전달한다. 상향 모델도 배정받은 단계의 권한을 따르며 실행 담당은 자신의 결과를 통합 수락하지 않는다.
- 통합 담당이 실행 결과의 결함을 정확히 발견한 것은 통합 모델의 실패가 아니다. 해당 결함의 수정 시도는 실행 작업에서 집계한다. 통합 자체의 조사·연결·판정 문제를 해결하지 못한 경우에만 통합의 재시도 정책을 적용한다.
- 이 정책이 적용되는 요청 범위에서 바로 위 단계로 한 번 상향하는 배정은 사전 승인된 것으로 본다. 지정된 시간·사용량·비용 한도와 환경 권한은 계속 지킨다. 필요한 기능·모델이 없거나 한도를 넘으면 인계한다. Codex Sol의 확인된 사용량 제한은 위 대체 규칙만 적용하며, 사용자 지정 총량 한도는 유지한다.
- 상향 모델의 1회 시도도 실패하면 해당 문제의 추가 수정·모델 변경을 멈춘다. 수동 모드에서는 사용자에게, 자동 모드에서는 총괄에게 실패 근거·시도 내역·남은 가설·영향·재개 조건을 보고한다. 총괄은 이를 사용자에게 알리고 해당 문제를 인계하며 다른 독립 작업의 진행 여부는 [11절](orchestration.md)을 따른다.
- 수동 모드에서는 현재 요청된 단계 안에서만 적용한다. 수정 실행이나 다음 제작 단계의 별도 요청을 대신하지 않는다. 사용자가 다른 한도를 지정하면 우선하며, 중단 시 사실·시도·남은 가설·영향·재개 조건을 보고한다.
