# 실행

개정: 2026-11-08 · 관리 구조 버전: `5`

## 7. [실행]

### 입력과 수행

목표, 범위, 입력, 산출물, 완료 조건과 필수 검증 목표를 확인한다. 작업지시서가 있으면 주 입력으로 읽고, 없으면 사용자 메시지나 기존 자료에서 필요한 정보를 정리한다. 총괄 배정 중 병렬 수행이 불가능한 상황을 발견하면 [11절](orchestration.md)의 충돌 보고·대기·재배정 절차를 따른다.

1. 대상 ID의 현재 위치·담당·개정·입력 버전·시작 조건을 확인한다. 구조 전환이 필요하면 [구조·전환 안내](records.md)에 따라 인계하고 영향받는 쓰기를 보류한다. 충족된 작업만 [4절](records.md)에 따라 진행 중으로 이동한다.
2. 지정 범위의 결과물을 만든다. 설계 선택·가정 변경의 이유와 영향을 기록하고, 범위 내 선택·오류 수정은 처리하되 중요한 요구사항 변경은 [1절](common.md)에 따라 확인한다.
3. 실제 결과물을 완료 조건에 대조한다. 변경 범위, 영향받은 연결 부분, 경계 조건과 주요 위험을 규모에 맞게 검토한다.
4. 테스트·관찰·렌더링·시뮬레이션 등 적절한 방법으로 최소한의 충분한 검증을 수행하고 선택 이유를 짧게 남긴다. 필수 목표를 유지하며 범위 내 오류는 수정하고 영향받은 검증만 다시 수행한다. 접근 불가능한 항목은 [5절](records.md)에 따라 인계한다.
5. 동일 문제의 실패·재시도는 [담당·소유권](common.md)·[모델·재시도](models.md)을 따른다. 중단 시 확인된 사실·시도·남은 가설·영향·재개 조건을 남긴다.
6. 자기 작업 문서에 [4절](records.md)의 수행·검증 결과와 이력을 갱신하고 [5절](records.md)의 대상 버전·증빙을 연결한다. 수정 실행은 수정 대상·상위 Task·지시서 개정을 명시한다. `index.md`에 반영할 사항은 다음 조치로 인계한다.

### 종료 조건

결과물과 자체 검증 보고를 제출하면 실행을 종료한다. 정상 제출은 검토 대기, 수정 필요·막힘은 [4절](records.md), 사용자 검증 대기는 [5절](records.md)을 따른다. 수락을 기다리며 제작을 계속하거나 통합을 직접 시작하지 않는다. 종료 보고는 [10절](common.md), 후속 배정은 수동·자동 모드의 요청 권한을 따른다.
