# 위임·인계·사용량

개정: 2026-11-17 · 관리 구조 버전: `5`

위임·담당 교체 때 적용한다. 작업 경계와 인계 비용을 고려해 별도 실행 담당자·대화에 우선 배정하되 직접 수행에도 최초 모델 기준을 적용한다. 중요한 결과는 규모가 작아도 독립 검토를 고려한다. 선행 조건·입력 버전이 안정적이고 수정 파일·공유 자원 소유권이 겹치지 않을 때만 병렬화한다. 자동 배정의 판단·조정은 [총괄](orchestration.md)을 따른다.

인계 메시지는 역할·Task ID·현재 클라이언트·접근 방식, 프로젝트/작업 문서 절대 경로, 고정 워크플로우 커밋·경로, 지시서 개정·입력/제출 버전, 이번 변경·다음 행동으로 제한한다. 상세 결정·위험·증빙은 원본을 참조하고 별도 인계 사본을 만들지 않는다. 필수 원문·자료에 실제 접근할 수 있는지 확인하며 다른 worktree나 MCP 호스트 경로를 로컬 경로로 간주하지 않는다.

환경이 지원하면 전체 대화를 상속하지 않고 필요한 입력만 전달한다. 생략할 사용자 결정·제약은 먼저 작업 문서에 보존한다. 새 담당자는 필수 원문을 읽고 같은 담당자는 현재 컨텍스트에 있는 변경 없는 자료를 다시 읽지 않는다. 컨텍스트 유실 시 필요한 원문을 복구한다. 상속 차단이 불가능하면 그 제한을 알린다. 범위·수락 기준·소유권·버전·미제출 변경·실패 누계·증빙·미해결 문제를 인계에서 잃지 않는다.

## 비용과 대기

- 환경이 제공하는 입력·캐시 입력·출력·추론 사용량만 역할·시각·관측 범위·누락 여부와 함께 한 곳에 집계한다. 출력에 포함된 추론, 상위에 포함된 하위 사용량을 중복 합산하지 않는다. 수집을 위한 반복 조회·별도 시스템 구축은 기본 범위가 아니다.
- 인계문 출력과 인계 후 원문 입력도 비용이다. 부모 컨텍스트·전역 지침과 실제 파일 읽기를 구분하며 관측 없는 절감률은 제시하지 않는다. 호출 없는 대기를 토큰 소비로 추정하지 않는다.
- 완료 이벤트·대기 도구를 사용하고 짧은 간격의 상태 추론을 피한다. 안내는 의미 있는 변경·막힘·결정·완료와 환경의 필수 진행 안내를 따른다.
- 공통 모델 프로필·제약은 참조하고 작업별 실제 설정·예외만 기록한다. 동일 결과·확인 불가 문구를 여러 원장에 복제하지 않는다.
- 독립 제작·검증·인계 가능한 산출물을 작업 단위로 삼는다. 파일·함수마다 분할하지 않으며 연속된 작은 변경은 묶는다. 제출 전 자체 검증 수정은 원 Task에서 처리한다.
- 검증된 기존 도구로 목록 집계·상태 이동을 처리할 수 있지만 권한·이력을 보존하고 수락 판단을 대신하지 않는다. 새 자동화 구축은 별도 범위로 정한다.
