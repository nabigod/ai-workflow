# 사용자검증

개정: 2026-11-08 · 관리 구조 버전: `5`

## 13. [사용자검증] 수동 사용자 시험 안내와 결과 기록

### 범위와 준비

확정된 기준에 따라 사용자가 수행할 시험을 안내하고 결과를 기록한다. 모호한 기준을 임의 확정하거나 제품 코드·설정·결과물을 수정하지 않으며, 새 환경 구축·원격 장비 제어·작업 수락을 수행하지 않는다. 기록 소유권은 [담당·소유권](common.md)·[모델·재시도](models.md), 작업 상태와 수락 권한은 [4절](records.md), 검증 근거·버전·환경 범위는 [5절](records.md)을 따른다.

단일 프로젝트가 분명하고 범위를 생략하면 그 프로젝트의 미해결 사용자 검증 전체를 대상으로 한다. 프로젝트가 여러 개이면 대상을 확인한다. 작업 문서 안의 개별 검증 항목을 단위로 삼고 기존 식별자를 우선 사용한다. 없으면 문서 안에서 고유하고 재개 시 유지되는 식별자를 부여하며 새 `VAL` 작업이나 별도 원장을 만들지 않는다.

### 한 항목씩 진행하는 절차

1. 현재 작업 문서·기준·대상 버전·의존 조건과 갱신 소유권을 확인한다. 미해결 항목 전체를 작업 ID·항목 식별자·검증 내용·대상 버전·준비 조건·의존 관계·검증 상태로 먼저 제시하고 수행 순서를 정한다.
2. 한 번에 한 항목의 실행 위치·운영체제·shell, 준비 조건, 복사 가능한 실제 명령, 기대 결과·실패 기준과 회신할 자료를 안내한다. 물리 조작·GUI·육안 관찰은 필요한 수동 절차를 병기한다. 명령을 정할 환경 정보가 부족하면 필요한 정보만 질문하고, 실제 유효성을 확인할 수 없는 명령은 만들어내지 않는다.
3. 사용자에게 결과 제출을 안내하고 대화를 넘긴다. 일반 결과 대기는 단계 중단이 아니며, 회신을 같은 단계의 계속으로 처리한다. 항목마다 명령 재호출·진행 승인을 요구하거나 응답을 반복 조회하지 않는다.
4. 회신은 [5절](records.md)에 따라 대상 버전·시험 조건·사용자 수행 근거를 확인한다. 항목 상태와 증빙을 해당 원본 작업 문서의 최신 결과·이력에 반영한다. 근거가 부족하면 필요한 확인만 요청하고 통과로 처리하지 않는다.
5. 기록 후 통과·실패·대기 현황, 남은 항목·차단 사유·다음 행동을 알린다. 실패에 의존하는 항목은 보류하고 다음 독립 항목으로 진행한다. 새로운 근거 없이 같은 시험을 반복하지 않는다.

### 종료·중단·인계

항목이 없으면 없음으로 보고하며 통과나 수락을 가정하지 않는다. 진행 가능한 항목을 처리했거나 외부 입력·수정 없이는 더 진행할 수 없으면 [10절](common.md)에 따라 결과·미해결 항목·다음 조치를 인계한다. 사용자 결과를 기다리는 중이면 제출할 자료와 진행 상태를 안내하고 같은 단계의 회신을 기다린다.

모든 항목이 통과해도 최종 수락은 통합 담당자가 한다. 수동 모드에서는 `[통합]` 요청으로, 유효한 자동 모드에서는 총괄 배정으로 검토한다. 명시적 중단·재개는 [4절](records.md), 활성 총괄과의 소유권 조정·종료된 총괄의 재개는 [11절](orchestration.md)을 따른다.
