# 단계별 워크플로우 진입

개정: 2026-11-08 · 관리 구조 버전: `5`

사용자가 단계별 워크플로우를 요청할 때 적용한다. 문서 검토·개정이나 인용된 태그는 프로젝트 실행 명령이 아니다. 기본은 수동이며 직접 요청한 단계만 수행한다. `[총괄]`은 명시적으로 호출해야 한다.

## 버전과 읽기 범위

작업 시작 시 선택한 스냅샷 절대 경로와 Git 커밋을 해당 작업의 적용 버전으로 고정한다. 하위 에이전트도 같은 경로·커밋을 전달받는다. 진행 중에는 다른 PC나 작업의 갱신으로 활성 버전이 바뀌어도 기존 사본을 계속 사용한다. 기존 작업 재개에도 고정 버전을 유지하며, 명시적 개정 적용 요청이 있을 때 변경 영향을 확인한다.

상세 규칙은 아래 표에 따라 파일로 읽는다. 현재 컨텍스트에 있는 동일 개정의 본문은 다시 읽지 않는다. 새 담당자나 컨텍스트 유실·압축으로 필요한 본문이 없는 경우에는 다시 읽는다. 요약이나 파일명만으로 필수 본문을 읽었다고 간주하지 않는다. 원본에 접근할 수 없으면 필요한 본문을 인계받거나 접근 제한을 보고한다.

| 계획 | [공통](common.md), [모델](models.md), [기록](records.md), [품질](quality.md), [계획](planning.md) |
| 실행 | [공통](common.md), [모델](models.md), [기록](records.md), [품질](quality.md), [실행](execution.md) |

각 역할은 해당 작업지시서·필수 입력·영향받는 증빙을 추가로 읽는다. 링크가 있다는 이유만으로 다른 역할 문서를 전부 따라 읽지 않는다. 현재 판단에 필요한 인계 규칙은 해당 링크에서 확인한다.

## 조건부 문서

- 계획·통합에서 구구조 전환이 필요할 때만 [구조 전환](migration.md)을 읽는다. 실행 담당자는 전체 전환을 수행하지 않는다.
- 현황판 제작·수정·검토를 요청받았을 때만 [현황판](dashboard.md)을 읽는다.
- 총괄이 배정한 실행·통합 담당자는 [총괄](orchestration.md)의 `병렬 수행 불가 발견 시 보고와 조정` 절을 추가로 읽는다. 총괄 지시 없이 충돌 작업을 재개하지 않는다.
- [사용자 가이드](../docs/user-guide.md), [설치 안내](../docs/installation.md)는 해당 설명·설치 요청에만 읽는다.

최종 수락은 통합 담당자만 한다. 최초 실행·REV·사용자검증·커밋목록은 1단계 모델이다. 실행·통합의 동일 문제는 지정 모델로 최초 시도 포함 2회 실패 후 바로 위 단계로 1회만 시도하며, 다시 실패하면 중단·보고한다. 전체 규정과 사용자 명시 예외는 위 필수 문서가 기준이다.
