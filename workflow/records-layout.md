# 관리 구조 생성

개정: 2026-11-17 · 관리 구조 버전: `5`

## 2. 위치와 운영 방식

프로젝트 관리 구조를 처음 만들 때 읽는다. 목표·범위·입력·완료 조건·산출물 위치는 기존 지시에서 확인한다. 계획은 인터뷰로 요구사항을 확정하고 실행·통합은 누락·충돌한 요구사항을 임의 확정하지 않는다. 실행은 분야에 따라 구현·조사·작성·제작을 뜻한다. 수동·자동은 같은 검증·수락 기준을 쓰며 자동은 승인 범위의 후속 배정 권한만 추가한다.

단순 작업은 목표·범위·완료 조건·결과물·검증·남은 문제·다음 행동을 짧은 작업 문서 하나에 기록한다. 충분한 사용자 지시의 간소 단독 실행은 별도 지시서 없이 가능하다. 기록량과 모델·담당은 독립적이며 다음 단계로 자동 전환하지 않는다. 이미 표준 구조이면 작은 작업도 그 안에서 변경 부분만 기록한다. 의존성·담당·인계가 늘면 계획·통합에 표준 전환 필요를 보고하되 기존 구조 전환은 명시적 요청에 따른다.

사용자가 정한 프로젝트 루트의 `.ai-work/<project-id>/`가 기본이다. 파일·프로젝트 구조로 경계를 확인하고 사용자 지정을 Git 루트보다 우선한다. 현재 디렉터리·앱 설정·스킬 위치를 자동 루트로 간주하지 않는다. 여러 후보로 모호할 때만 묻는다. 기존 관리 위치가 있으면 알리고 임의로 이동하거나 중복 생성하지 않는다. 프로젝트 없는 대화는 사용자 접근 가능한 작업/출력 위치를 쓰며 저장 불가 시 대화로 제공하고 저장했다고 주장하지 않는다.

## 표준 구조

여러 산출물·복잡한 의존성·병렬 작업·장기 인계에 사용하며 실제 필요한 파일·상태 폴더만 만든다.

| 위치 | 내용 |
|---|---|
| index.md | 목표·주요 결정·대상·담당·현재 작업 링크·다음 조치와 갱신 시각 |
| plan.md | 요구사항·공통 설계/기준·사용자 결정; 개별 지시서는 링크 |
| work-items/상태/ID.md | 작업별 지시·수행 결과·검증·제출/판정 이력의 단일 원본 |
| evidence/T-xx/ | 상위 Task와 모든 하위 작업의 고정 증빙; 상태 없음 |
| integration.md | 작업 간 연결·추가 검증·전체 판단; 개별 판정은 링크 |
| migration.md | 명시적 구조 전환 시에만 생성 |
| summary.md | 통합이 전체 완료를 판정한 때만 생성 |
| dashboard/ | 요청·제작한 읽기 전용 현황판의 index.html·status.json |

상태 폴더는 [작업 상태](records-state.md#상태와-권한)를 따른다. 완료 문서도 work-items/90-done에 유지하고 별도 reports/·99-archive를 만들지 않는다. 취소 폴더는 취소 발생 시에만 만든다. 결과 요약을 증빙에 복제하지 않으며 소스·최종 산출물은 프로젝트의 적절한 고정 위치에 둔다. 임시·대용량 파일은 별도 관리한다.

`.ai-work/` 아래 새 이름은 ASCII 영문자·숫자·하이픈·밑줄·마침표만 사용한다. project-id는 짧고 고유하게 유지한다. 작업 파일은 ID.md, 공통 파일은 위 고정 영문 이름, 증빙은 `<작업ID>-<종류>-<번호>.<확장자>`다. 종류는 test-log, external-evidence처럼 소문자 영문·하이픈으로 통일하고 번호는 작업 ID·종류별로 부여한다. 과거 판정의 증빙을 덮어쓰지 않는다. 이름 제한은 한국어 본문을 제한하지 않는다. 기존 이름 변경은 복구·참조를 확인하는 명시적 전환 범위에서만 한다.

원본의 위치·소유권은 [공통](common.md), 결과·상태는 작업 기록, 증빙은 [검증 기록](records-evidence.md)이 기준이다. 새 구조 생성은 기존 프로젝트의 전체 전환 허가가 아니다.
