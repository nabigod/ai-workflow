# 통합

개정: 2026-11-08 · 관리 구조 버전: `5`

## 8. [통합]

### 입력과 수행

전체 목표, 결합할 결과물·버전과 관계, 공통 기준과 수락 기준을 확인한다. 계획과 작업 문서의 지시·최신 결과·이력을 읽고, 문서가 없으면 필요한 정보를 기존 자료에서 정리한다. 없는 문서를 형식적으로 소급 작성하지 않는다. 총괄 배정 중 병렬 검토·결합이 불가능한 상황을 발견하면 [11절](orchestration.md)의 충돌 보고·대기·재배정 절차를 따른다.

1. [2절](records.md)의 필요한 구조 전환을 마친 뒤 제출 시각·실제 산출물 버전을 확인하고 검토 대상을 [4절](records.md)에 따라 검토 중으로 이동한다.
2. 요구사항별 누락·중복·충돌과 검증 근거를 확인한다. 요약만으로 수락하지 않고 주요 결과물과 중요한 증빙을 직접 확인한다.
3. 정해진 인터페이스·순서로 결과물을 결합한다. 새 공통 기준이 필요하면 이유와 기존 결과물에 미치는 영향을 기록한다.
4. 연결 작업과 공통 서식 정리, 의미·동작·인터페이스를 바꾸지 않는 단순 수정은 허용 범위에서 처리한다. 개별 결과물의 실질 내용을 바꾸거나 경계가 불명확하면 수정 실행으로 분리한다.
5. 수정이 필요하면 [4절](records.md)의 ID·상태 규칙에 따라 REV를 생성하고 관련 작업에 연결한다. [6절](planning.md)의 지시서 항목에 문제·근거, 수정 대상과 버전, 원하는 결과·허용 범위·영향받는 작업·필수 검증을 명시한다. 같은 수정의 재검토에서는 기존 ID와 개정 규칙을 따른다.
6. [5절](records.md)에 따라 유효한 검증은 재사용하고 연결·변경 영향·누락·위험에 필요한 추가 검증만 수행한다. 통합 자체의 실패·재시도는 [담당·소유권](common.md)·[모델·재시도](models.md)을 따른다.
7. 개별 판정은 [4절](records.md)·[5절](records.md)에 따라 해당 작업 문서에 기록한다. `integration.md` 또는 간소 기록에는 범위 전체의 요구사항 충족 여부, 연결·추가 검증, 직접 변경과 전체 판단을 남기고 개별 판정에 연결한다. `index.md` 반영은 [담당·소유권](common.md)·[모델·재시도](models.md)의 권한을 따른다.

### 종료 조건과 수정 인계

- 개별 작업의 필수 조건을 충족하면 [4절](records.md)에 따라 수락한다. 프로젝트 전체의 필수 요구사항·검증을 충족하고 미해결 수정이 없으며, 취소 요구사항의 제외·대체 승인까지 확인한 경우에만 전체 완료를 판정한다. 일부 범위의 수락을 전체 완료로 확대하지 않는다.
- 표준 방식의 전체 완료 때만 `summary.md`에 결과물 경로·사용 방법, 주요 결정, 요구사항 충족 상태, 검증 근거와 합의된 제한을 남긴다. 비필수 제한은 명시할 수 있지만 필수 조건을 낮추지 않는다. 미완료이면 통합 기록·남은 작업을 인계하며 새 완료 요약을 만들지 않는다. 이전 요약은 과거 버전임을 표시한다.
- 수정이 필요하면 지시서와 영향을 인계하고 종료한다. 수동 모드에서는 별도 `[실행]`과 재통합 요청을 기다리고, 자동 모드에서는 총괄이 배정한다. 통합 담당자가 수정 구현까지 이어가지 않는다. 재통합은 수정 결과·영향받은 연결을 확인하고 REV와 원래 Task를 [4절](records.md)에 따라 각각 판정한다.
- 사용자 시험만 남으면 [5절](records.md)의 대기·인계 규칙에 따라 종료하고 필요한 `[사용자검증]` 요청을 안내한다. 종료 보고는 [10절](common.md)을 따른다.
