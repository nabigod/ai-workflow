## 12. 읽기 전용 현황판

### 목적·파일·표시 기준

현황판은 로컬 브라우저에서 보는 HTML을 기본으로 설계한다. 실제 제작·실행기 연결·중단 시험은 별도 요청한 작업으로 수행한다. 워크플로우 개정, 프로젝트 전환 또는 `[총괄]` 호출만으로 현황판을 자동 제작하거나 새 서버·환경을 설치하지 않는다. 현황판이 준비되지 않았으면 문서와 대화로 현황을 인계하며 실시간 화면이 있다고 보고하지 않는다.

사용할 경우 `.ai-work/<project-id>/dashboard/index.html`과 `status.json`을 둔다. status.json은 작업 문서와 실행 정보에서 생성한 읽기 전용 스냅샷이며 원본 상태 원장이 아니다. 이를 직접 편집해서 작업 상태나 수락을 바꾸지 않는다. 표시용 스냅샷 갱신 담당은 수집기 하나로 정하고 총괄의 index.md 갱신과 구분한다.

| 표시 영역 | 필수 내용 |
|---|---|
| 전체 진행 | 지정 대상·계획 버전, 상위 Task의 수락·진행·대기·막힘 수, 하위 유형별 별도 집계 |
| 총괄 | 실행 식별자·운영 상태·다음 행동·중지 이유·잔여 실행 확인 결과 |
| 에이전트 | 역할·요청 및 확인된 모델·담당 ID·실행/대기/종료/중단 상태·확인 시각 |
| 작업 | ID·제목·실제 상태 폴더·선행 조건·대기 이유·다음 담당·문서 링크 |
| 최근 이력 | 실행 시작·제출·반려·REV 시작·수락·중지와 대상 버전 |
| 사용량 | 확인 가능한 역할별 토큰·집계 대상·집계 시각·누락 여부·지정 한도 |
| 정보 신선도 | 문서 갱신 시각·실행 상태 관측 시각·수집기 갱신 시각·연결 상태 |

상위 Task, 하위 유형별 작업과 사용자 검증 항목을 별도로 집계한다. 검증 상태는 [5절](records.md)을 따르며 하위 작업·항목 통과를 상위 Task 수락으로 계산하지 않는다. 범위와 분모가 불명확하면 전체 백분율이나 예상 완료 시간을 표시하지 않는다. 작업 상태와 실제 에이전트 실행 상태를 구분한다.

### 수집·갱신과 토큰

- 가벼운 수집 프로그램이 원본 문서와 실행 이벤트·상태 조회 결과로 스냅샷을 만들고 화면이 이를 읽는다. 예를 들어 5초 화면 갱신은 모델 호출 없이 처리한다. 총괄은 배정·판단에 집중하며 화면 갱신을 위해 매번 호출하지 않는다. 기존 제작·검토·요약 호출의 사용량은 [담당·소유권](common.md)·[모델·재시도](models.md)에 따라 집계한다. 화면 갱신 시각을 실행 정보의 관측 시각으로 표시하지 않는다.
- 사용 가능한 실행 인터페이스에서 관측 가능한 정보만 표시한다. 토큰·모델·하위 실행 상태를 수집할 수 없으면 확인 불가로 표시한다. 정보 누락은 0, 종료 또는 정상 동작을 뜻하지 않는다.
- 수집기가 중단되거나 연결이 끊기면 마지막 관측 시각과 정보 지연·확인 불가를 표시한다. 총괄이 멈춘 뒤에도 오래된 실행 중 표시를 현재 사실로 오인하지 않게 한다. 화면 자체에서 갱신 시각의 경과를 확인할 수 있어야 한다.
- 로컬 파일의 브라우저 접근 제한 때문에 자동 갱신에 로컬 제공 기능이 필요할 수 있다. 기존 허용 환경을 활용하고 새 서버 실행·설치가 필요하면 별도 제작 범위에 포함한다. 정적 파일만 제공했다면 수동 새로고침 스냅샷임을 명시한다.

### 제어 기능의 경계와 검증

첫 버전은 조회·필터·문서 열기만 지원한다. 전체 중지·재개 버튼은 취소 전달과 중단 확인을 실행기에 연결하고 시험한 뒤 별도 개정으로 도입한다. 동작하지 않는 버튼이나 단순 화면 상태 변경을 실제 실행 제어처럼 제공하지 않는다.

현황판 제작 시 문서 상태와 실행 상태의 불일치, 수집기 연결 끊김, 누락된 사용량, 완료된 REV와 미완료 상위 Task, 원본 문서 이동에 따른 링크 갱신을 검증한다. 자동 운영의 전체 중지 기능은 별도로 실행 중 하위 에이전트·명령 중단, 완료 이벤트와 중지 요청의 경합, 갑작스러운 상위 중단, 상태 정리 실패, 명시적 재개 전 배정 금지를 시험한다. 현재 환경에서 시험하지 못한 기능은 미검증으로 남기고 사용자에게 인계한다.
