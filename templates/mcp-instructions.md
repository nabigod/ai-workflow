# 단계별 워크플로우 연결 (MCP)

단계별 프로젝트 운영 요청과 명시적인 연결 확인에 적용한다. 일반 질문이나 워크플로우 문서 검토를 프로젝트 실행으로 해석하지 않는다.

- 공통 배포 정보는 `ai-workflow` MCP의 `get_workflow_status`로 읽는다. 반환된 `active.commit`과 `snapshot_uri`를 새 작업의 적용 버전으로 고정한다. 호스트의 Windows/WSL 절대 경로는 원격 프로젝트의 로컬 경로로 해석하지 않는다.
- `read_workflow_document(commit=<고정 커밋>, path="workflow/entry.md")`로 진입 문서 본문을 읽은 뒤 해당 역할의 필수 문서만 같은 도구·커밋으로 읽는다. entry.md를 읽지 않고 역할별 목록을 추정하지 않는다. 문서의 상대 링크도 같은 스냅샷 내 경로로 해석한다.
- `sync_status`는 PC에서 기록한 마지막 원격 확인 결과이고 `observed_at`·문서의 `read_at`은 이번 읽기 시각이다. MCP 읽기는 원격 fetch가 아니다. `remote_checked_this_call`을 확인하고 기존 사본을 현재 원격 최신이라고 부르지 않는다. 최신 확인이 필요하면 PC의 관리 명령으로 sync한 결과를 확인하며 원격 서버에서 PC 경로의 sync 명령을 실행하지 않는다.
- 기존 작업은 기록한 커밋을 계속 지정한다. 진행 중 `get_workflow_status`가 다른 커밋을 반환해도 자동 전환하지 않는다. 고정 사본이 없거나 MCP 접근이 실패하면 임의의 최신 버전·로컬 경로로 대체하지 않고 접근 제한을 보고한다.
- 하위 에이전트에게 역할, 고정 커밋·snapshot_uri, 필수 문서의 묶음 내 경로, 대상 작업지시서·입력 버전을 전달하고 같은 MCP의 본문 읽기가 가능한지 확인한다. 지원하면 부모 대화 전체 상속을 끄고 필요한 입력만 전달한다. 생략할 사용자 결정은 작업 문서에 보존한다. MCP가 없는 담당자에게는 필수 원문을 인계하고 직접 MCP로 읽었다고 보고하지 않는다.
- 연결 확인만 요청받으면 status와 entry 본문만 읽고 역할별 필수 목록을 보고한다. 필수 문서의 본문 읽기와 목록 확인을 구분한다. 프로젝트 실행·동기화·파일 변경은 하지 않는다.
- 최초 지정 모델과 사용자검증·커밋목록의 1단계 배정, 실패 시 상향과 통합 수락 권한은 읽은 워크플로우 원문을 따른다.
