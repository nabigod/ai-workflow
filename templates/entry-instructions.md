# 단계별 워크플로우 연결

단계별 프로젝트 운영 요청에만 적용한다. 일반 질문이나 워크플로우 문서 검토를 프로젝트 실행으로 해석하지 않는다.

- 공통 배포 정보: `{{ACTIVE_PATH}}`. 같은 폴더의 `sync-status.json`에서 마지막 원격 확인 성공 여부·시각도 확인한다.
- 새 작업은 위 JSON의 `entry` 절대 경로를 읽고 역할별 필수 문서만 읽는다. `commit`과 `snapshot`을 작업의 적용 버전으로 고정한다. 파일명이나 개정 날짜만으로 최신임을 판단하지 않는다.
- 새 작업 전에 원격 확인이 필요하면 허용된 네트워크·파일 접근 범위에서 다음 명령을 한 담당자가 실행한다: `{{SYNC_COMMAND}}`. 하위 에이전트는 동기화를 실행하지 않는다. 이미 진행 중인 작업은 활성 포인터를 다시 따라가지 않는다.
- 하위 에이전트에게 역할, 고정 커밋, 스냅샷과 필수 문서 절대 경로, 대상 작업지시서·입력 버전을 전달하고 접근을 확인한다. 환경이 지원하면 부모 대화 전체 상속을 끄고 필요한 입력만 전달한다. 생략할 사용자 결정은 먼저 작업 문서에 보존하며 필수 규칙·원자료 읽기는 생략하지 않는다.
- 원격 확인 실패 시 기존 사본을 최신이라고 부르지 않는다. 적용 커밋·확인 실패를 보고하며 최신 버전이 필수이면 시작을 보류한다.
- 기존 작업 재개 시 기록된 스냅샷을 사용한다. 문서 경로를 읽을 수 없으면 원문 접근 또는 인계를 요청한다.
- 최초 지정 모델을 준수하고, 사용자검증·커밋목록은 1단계로 수행한다. 품질 문제에 따른 상향과 수락 권한은 읽은 워크플로우를 따른다.
