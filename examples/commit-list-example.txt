커밋리스트 예시

이 파일은 형식 확인을 위한 가상 변경 예시입니다.
예시 커밋 메시지 규칙: type(scope): 영문 변경 요약
실제 작성 시 대상 디렉토리의 명시된 규칙을 우선 적용합니다.
별도 규칙이 없으면 HEAD를 포함한 최근 최대 30개 커밋의 메시지에서
제목·본문 형식, 언어, 접두어와 범위 표기 관례를 확인합니다.
예시 shell: Bash. 실제 작성 시 사용자의 shell에 맞게 경로를 인용합니다.
아래 명령의 파일 경로는 모두 프로젝트 루트 기준 상대 경로입니다.
가상 경로이므로 이 예시 명령을 실제 프로젝트에서 실행하지 마세요.
실제 목록에서는 현재 커밋할 그룹의 명령 줄만 복사해 프로젝트 루트에서 실행하고,
해당 커밋을 마친 뒤 다음 그룹으로 진행합니다. 파일 전체를 실행하지 않습니다.
커밋 번호는 이 목록의 순서이며 커밋 메시지에 포함하지 않습니다.

============================================================
커밋 1
============================================================

커밋 메시지:
fix(serial): handle receive timeouts without discarding buffered bytes

Preserve incomplete frames across receive timeouts and report the
timeout to the caller. Add coverage for partial frame recovery.

스테이징 명령 — 프로젝트 루트에서 실행:
git add -- "src/serial/receiver.rs"
git add -- "src/serial/error.rs"
git add -- "tests/serial_receive_timeout.rs"

============================================================
커밋 2
============================================================

커밋 메시지:
feat(config): make the serial receive timeout configurable

Load the receive timeout from configuration and validate its range.
Document the default value and configuration format.

스테이징 명령 — 프로젝트 루트에서 실행:
git add -- "src/config/serial.rs"
git add -- "config/default.toml"
git add -- "tests/serial_config.rs"
git add -- "docs/configuration.md"

============================================================
커밋 3
============================================================

커밋 메시지:
docs(serial): explain timeout diagnosis and recovery

스테이징 명령 — 프로젝트 루트에서 실행:
git add -- "docs/serial-troubleshooting.md"

============================================================
작성 범위
============================================================

각 명령은 한 파일 전체의 스테이징을 전제로 합니다.
실제 스테이징·커밋 전에는 현재 diff와 staged 내용을 목록에 대조합니다.
기존 staged 변경도 커밋에 포함될 수 있습니다.
같은 파일은 하나의 추천 커밋에만 포함합니다.
한 파일이 여러 변경에 걸치면 관련 묶음을 합치고,
분리가 꼭 필요한 경우에는 해당 묶음을 보류하고 이유를 알립니다.
라인·패치 단위 분할과 별도 분할 관리 기록은 만들지 않습니다.

.ai-work/ 관리 기록과 이 커밋리스트 파일 자체는 기본 제외합니다.
내부 작업 ID와 관리 경로는 추천 커밋 메시지에 넣지 않습니다.
목록 작성은 git add 또는 git commit 실행을 포함하지 않습니다.
